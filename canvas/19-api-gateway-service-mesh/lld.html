The full 10-step pipeline — GatewayService.handleRequest

grounded in real code
from service/GatewayService.java
public HttpResponse handleRequest(HttpRequest request) {
  String traceId = UUID.randomUUID().toString().substring(0, 8);

  // Step 1: Create request context
  RequestContext ctx = new RequestContext(request);

  // Step 2: Route matching
  Optional<Route> matchedRoute = routingService.matchRoute(request);
  if (matchedRoute.isEmpty()) return buildErrorResponse(404, "No route", traceId);
  Route route = matchedRoute.get();
  ctx.setRoute(route);

  // Step 3: Authentication
  AuthResult authResult = authService.authenticate(request);
  if (!authResult.isAuthenticated()) return buildErrorResponse(401, "...", traceId);
  ctx.setAuthResult(authResult);

  // Step 4: Authorization
  if (!authService.authorize(authResult, route)) return buildErrorResponse(403, "...", traceId);

  // Step 5: Rate limiting
  RateLimitResult rl = rateLimitService.checkRouteRateLimit(ctx);
  if (!rl.isAllowed()) return buildErrorResponse(429, "Rate limit", traceId);

  // Step 6: Circuit breaker check
  String targetService = route.getTargetService();
  if (!circuitBreakerService.allowRequest(targetService))
      return buildErrorResponse(503, "Circuit OPEN", traceId);

  // Step 7: Load balancer — select instance
  Optional<ServiceInstance> instance = loadBalancerService.selectInstance(targetService, request);
  if (instance.isEmpty()) return buildErrorResponse(503, "No healthy instances", traceId);

  // Step 8: Forward to upstream (simulated 10–100 ms latency, 5 % failure)
  long latencyMs = ThreadLocalRandom.current().nextLong(10, 101);
  boolean requestFailed = ThreadLocalRandom.current().nextDouble() < 0.05;

  // Step 9: Record success/failure in circuit breaker
  if (requestFailed) {
    circuitBreakerService.recordFailure(targetService);
    return buildErrorResponse(502, "Upstream error", traceId);
  }
  circuitBreakerService.recordSuccess(targetService);

  // Step 10: Build response with traceId header
  return new HttpResponse.Builder(200)
      .body("{\"service\":\"" + targetService + "\", ...}")
      .header("X-Trace-Id", traceId)
      .header("X-Gateway-Service", targetService)
      .header("X-Gateway-Instance", instance.get().getAddress())
      .latencyMs(latencyMs)
      .build();
}
Fail-fast ordering matters: route (cheap, in-memory) → auth (JWT verify, ~0.5 ms) → rate-limit (~0.01 ms) → circuit-breaker (~0.001 ms) → LB (~0.01 ms) → forward. Cheapest & most-likely-to-reject filters run first. A rate-limited client never pays the JWT verify cost, and a rate-limited client of an OPEN circuit never even reaches LB.

from strategy/routing/PathBasedRoutingStrategy.java
public Optional<Route> route(HttpRequest request, List<Route> matchingRoutes) {
  if (matchingRoutes == null || matchingRoutes.isEmpty()) return Optional.empty();

  return matchingRoutes.stream()
      .sorted(Comparator
          .comparingInt(this::specificityScore).reversed()
          .thenComparing(Comparator
              .comparingInt((Route r) -> r.getPathPattern().length()).reversed()))
      .findFirst();
}

private int specificityScore(Route route) {
  String pattern = route.getPathPattern();
  if (pattern.equals("/**") || pattern.equals("**")) return 0;    // catch-all
  boolean hasWildcard = pattern.contains("*");
  if (!hasWildcard) return 100;                                    // exact match
  long wildcardCount = pattern.chars().filter(ch -> ch == '*').count();
  return (int) (50 - wildcardCount);
}

from strategy/loadbalancing/RoundRobinLoadBalancer.java
private final AtomicInteger counter = new AtomicInteger(0);

public Optional<ServiceInstance> selectInstance(List<ServiceInstance> instances, HttpRequest req) {
  if (instances == null || instances.isEmpty()) return Optional.empty();

  // Step 1: filter to healthy instances
  List<ServiceInstance> healthy = instances.stream()
      .filter(ServiceInstance::isHealthy).toList();
  if (healthy.isEmpty()) return Optional.empty();

  // Step 2: atomic round-robin selection
  int index = Math.abs(counter.getAndIncrement() % healthy.size());
  return Optional.of(healthy.get(index));
}

Default choice. Simple, thread-safe via AtomicInteger. Distributes evenly assuming instances are equally powerful and requests are roughly equal cost.

from strategy/loadbalancing/WeightedLoadBalancer.java

Weighted random selection using instance weight field. Instance with weight=3 gets 3× the traffic of weight=1.

// Simplified logic (real impl uses cumulative distribution)
int totalWeight = healthy.stream().mapToInt(ServiceInstance::getWeight).sum();
int r = ThreadLocalRandom.current().nextInt(totalWeight);
int acc = 0;
for (ServiceInstance i : healthy) {
  acc += i.getWeight();
  if (acc > r) return Optional.of(i);
}

When: canary deploys (v1 weight=95, v2 weight=5) — same code path, different weights. Also for heterogeneous instance sizes (large instances get more traffic).

from strategy/loadbalancing/ConsistentHashLoadBalancer.java
private static final int DEFAULT_VIRTUAL_NODE_COUNT = 150;

public Optional<ServiceInstance> selectInstance(List<ServiceInstance> instances, HttpRequest req) {
  List<ServiceInstance> healthy = instances.stream()
      .filter(ServiceInstance::isHealthy).toList();
  if (healthy.isEmpty()) return Optional.empty();

  // Step 1: build the hash ring with virtual nodes (150 per instance)
  TreeMap<Integer, ServiceInstance> ring = buildRing(healthy);

  // Step 2: hash the request path and find ceiling on the ring
  int requestHash = hash(req.getPath());
  Map.Entry<Integer, ServiceInstance> entry = ring.ceilingEntry(requestHash);

  // Step 3: wrap around if past the last node (ring is circular)
  if (entry == null) entry = ring.firstEntry();

  return Optional.of(entry.getValue());
}

private int hash(String key) {                // FNV-1a
  int h = 0x811c9dc5;
  for (int i = 0; i < key.length(); i++) { h ^= key.charAt(i); h *= 0x01000193; }
  return h & 0x7FFFFFFF;
}

When: cache-affinity — the same request path always routes to the same instance, so its local cache stays warm. Also for sticky sessions where you want (userId → same instance) without cookies.

public boolean allowRequest(String serviceName) {
  CircuitBreakerState breaker = getOrCreate(serviceName);
  CircuitState state = breaker.getState();

  switch (state) {
    case CLOSED -> { return true; }
    case OPEN -> {
      if (breaker.shouldAttemptReset()) {
        breaker.halfOpen();
        System.out.println("[CB] " + serviceName + ": OPEN -> HALF_OPEN (attempting reset)");
        return true;                       // allow ONE test request
      }
      return false;                        // still cooling down → deny
    }
    case HALF_OPEN -> { return true; }     // test request in flight
    default -> { return false; }
  }
}

public void recordSuccess(String serviceName) {
  breaker.recordSuccess();
  // If HALF_OPEN and successCount == SUCCESS_THRESHOLD → transition to CLOSED
}

public void recordFailure(String serviceName) {
  breaker.recordFailure();
  // If CLOSED and failureCount == FAILURE_THRESHOLD → trip to OPEN
  // If HALF_OPEN → immediately trip back to OPEN (recovery failed)
}

HALF_OPENCLOSEDsuccessCount hits SUCCESS_THRESHOLD (default 3 consecutive successes)

ConstantDefaultTrade-off if you change it
DEFAULT_FAILURE_THRESHOLD5Lower → trips faster (may over-react to transient blips). Higher → slower to protect callers.
DEFAULT_SUCCESS_THRESHOLD3Lower → recovers faster (risk of premature CLOSED). Higher → slower to fully recover.
DEFAULT_OPEN_DURATION_MS30_000 (30 s)Lower → probes more often (thundering-herd risk). Higher → outages last longer than needed.

Advanced: production circuit breakers use error-rate percentage (e.g., open if >50 % of last 100 requests failed) rather than consecutive-count — more robust to sparse-traffic services.

         → circuitBreakerEngine.allowRequest(name)  // state machine

         → loadBalancingStrategy.selectInstance(healthy, request)

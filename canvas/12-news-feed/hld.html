A

Problem & requirements

clarify first
functional
  • Publish a post — text, image, video, link or poll (see ContentType); poster sees their own post immediately.
  • Generate feed — personalized, ranked (not pure chronological) merge of posts from friends + celebrities.
  • Engagement — like / comment / share; idempotent likes; live counter updates.
  • Follow / unfollow — bidirectional social graph; auto-detect celebrities.
  • Real-time updates — WebSocket "N new posts available" banner, live engagement counts.
  • Infinite scroll — cursor-based pagination (20/page) with gap detection.
non-functional
  • Feed latency p99 < 200 ms — cache-first read path.
  • Publish latency p99 < 300 ms (sync); fan-out is async.
  • Real-time push p99 < 1 s; fan-out completion p99 < 5 s for normal users.
  • Availability 99.99% — a blank feed is worse than a stale one → AP system.
  • Consistency — feed eventually consistent (5–10 s OK); social graph strongly consistent (drives fan-out correctness).
  • Read : Write ≈ 100 : 1 — optimise aggressively for the read path.
B

Back-of-envelope estimation

1 B users · 500 M DAU · avg 300 follows
Post QPS~6K/s
Post peak~17K/s
Feed QPS~60K/s
Feed peak~175K/s
Impressions~50B/day
Timeline / user~40 KB
Timeline cache~20 TB
Media / day~290 TB
Celebrity ≥1 M followers
Celeb count~100K users
Derivation: 500 M DAU × 5 posts/day × 20% active posters ≈ 500 M posts/day → 6 K writes/s · reads ≈ 100× ≈ 60 K/s · peak ×3. Timeline cache: 500 entries × ~80 B (postId+score) ≈ 40 KB/user · 500 M DAU ≈ 20 TB across ~40 Redis shards. → full math on canvas 3 & F3 · Estimation
The celebrity math that kills pure push: 50 M followers × ZADD @ 100 K/s per pipeline = 500 s ≈ 8 min of fan-out per celebrity post. Times 500 K celebrity posts/day = 2.5 trillion writes/day just for celebrities. Hybrid eliminates all of them.

E

Data model

read-optimised · denormalised
Cassandra — posts (user timeline)
CREATE TABLE posts (
  post_id       BIGINT,   // Snowflake — time-sortable
  user_id       BIGINT,
  content       TEXT,
  content_type  TEXT,     // TEXT/IMAGE/VIDEO/LINK/POLL
  media_urls    LIST<TEXT>,
  like_count    INT,      // denormalised counter
  comment_count INT,
  share_count   INT,
  created_at    TIMESTAMP,
  PRIMARY KEY (user_id, post_id)
) WITH CLUSTERING ORDER BY (post_id DESC);
// posts_by_id (PK post_id) — hydration lookup

Partition by user_id ⇒ author timeline co-located. Cluster by post_id DESC ⇒ latest first for free — no ORDER BY at read time.

Redis — timeline cache (per-user ZSET)
// Write (fan-out worker):
ZADD timeline:{user}  score  post_id
ZREMRANGEBYRANK timeline:{user} 0 -501  // keep top 500
EXPIRE timeline:{user} 604800           // 7 days

// Read (feed):
ZREVRANGEBYSCORE timeline:{user}
  +inf -inf LIMIT 0 20                  // top page
ZREVRANGEBYSCORE timeline:{user}
  (5.42 -inf LIMIT 0 20                 // page 2, cursor

Sorted Set. Member = post_id, score = ranking_score. ~40 KB/user; ~20 TB across the DAU. Post content lives in a separate post:{id} hash (24 h TTL) for hot hydration.

Two tables in Cassandra, one purpose: posts partitioned by user_id for the user timeline (celebrity pull), and posts_by_id partitioned by post_id for hydration during feed read. Same data, indexed twice — the price of a KV store is dual-writes.
F

Key design choices (deep-dived on canvas 3)

defend these
fan-out

Hybrid (push + pull)

Push for < celebrity threshold, skip for celebrities (pulled at read). Eliminates 2.5 T writes/day. → canvas 3 · Fan-out

ranking

Algorithmic scoring

affinity × recency_decay × engagement_boost × content_type_weight. Best-friend's mundane post beats a stranger's viral post. → canvas 2 · LLD

pagination

Cursor-based

cursor = {score}_{post_id}. Stable under real-time inserts — no duplicates, no misses. Gap-detection banner instead of jumping. → canvas 3

consistency

AP · eventually

Feed 5–10 s stale is fine; blank feed at 175 K/s is not. Social graph is the CP exception (drives fan-out correctness).

storage

Cassandra + Redis + PG + S3

Right store per access pattern: KV posts (Cassandra), ranked timelines (Redis ZSET), user + graph source-of-truth (Postgres), media (S3+CDN).

real-time

WebSocket + banner

Push just a "N new posts" notification (~100 B), not the content. Banner lets the user control when to see it — no scroll jank.

Glossary — one-liners

terms used above
Fan-out on writepush post_id into every follower's timeline at publish time
Fan-out on readpull latest posts from each followed user at feed request time
Hybrid fan-outpush for normal users, pull for celebrities — the production answer
Celebrityuser above a follower threshold (10 K in code, ~1 M in production)
Timeline cacheper-user Redis Sorted Set of post_ids ranked by score
Affinityweighted sum of viewer→author interactions (likes, comments, shares, DMs)
Recency decayscore multiplier that shrinks with post age (exp or harmonic)
Cursor pagination"give me posts after this last-seen item" — stable under inserts
Gap detectionserver tells client N new posts arrived above cursor → banner
Snowflake ID64-bit time-sortable, coordination-free unique post_id

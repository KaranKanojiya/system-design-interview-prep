A

Problem & requirements

clarify first
functional
  • Shorten a long URL → unique short code; redirect the short code → original URL.
  • Optional custom alias & expiration (TTL); expired → HTTP 410 Gone.
  • Click analytics (count, time, referrer, geo); delete/deactivate a URL.
non-functional
  • Redirect latency < 50 ms p99 — cache-first is essential.
  • Availability 99.99% — a redirect must never fail (→ AP system).
  • Durability — once created, a URL stays resolvable. Scale 10B+ redirects/mo.
  • Short codes non-guessable; eventual consistency is acceptable.

E

Data model

key-value shaped
url_mapping (hot lookup)
short_code   VARCHAR(7)  // UNIQUE idx — hot path
original_url TEXT
created_at   TIMESTAMP
expires_at   TIMESTAMP   // nullable (TTL)
click_count  BIGINT      // denormalized
is_active    BOOLEAN     // soft delete

Unique index on short_code is the lookup key. Denormalized click_count avoids expensive COUNTs.

click_events (append-only)
event_id   UUID
short_code VARCHAR(7)
clicked_at TIMESTAMP
referrer   TEXT
user_agent TEXT
country    VARCHAR(3)   // from IP

Append-only stream → columnar store (ClickHouse). Never on the redirect hot path — it flows through Kafka.

F

Key design choices (deep-dived on canvas 3)

defend these
code generation

KGS (pre-generated keys)

No collisions, not guessable, no runtime hashing. Beats hash+truncate and auto-increment. → canvas 2 · LLD

storage

Cassandra / DynamoDB

Simple key-value pattern, write-heavy, horizontal scale, native TTL. Postgres works at this scale too.

consistency

AP · eventual

A redirect must never fail; 1–2 s propagation delay is fine. QUORUM writes, ONE reads. → canvas 3

Glossary — one-liners

terms used above
Cache-asideapp checks cache first; on miss, reads DB and backfills the cache
KGSKey Generation Service — hands out pre-made unique short codes
Base62[0-9a-zA-Z] encoding; 62⁷ ≈ 3.5 trillion 7-char codes
Statelessserver keeps no per-client state, so any instance can serve any request
Hot paththe latency-critical flow — here, the redirect
AP (CAP)favour Availability + Partition-tolerance over strong Consistency
QUORUMa majority of replicas must ack (durability) — W+R>N for overlap
301 vs 302301 is browser-cached (fewer hits); 302 always hits the server (analytics)
Denormalized counterstore click_count on the row to avoid COUNT queries
Thundering herdmany requests stampede the DB when a hot cache key expires
